# 海信按键映射与 Nexus Prime 的融合

参考上游 [Nexus Prime](https://github.com/LightyearXizIl/Nexus-Prime/tree/84bd723b1894594f6fa6f4f2cf1cace1f4ffd0c1) 的小米映射实现，按海信 USB 输入适配，不接入小米的蓝牙专用钩子。

## 上游实现与对应接入

| 层次 | 上游小米实现 | 海信接入 |
| --- | --- | --- |
| 设备输入 | BLE / HID Tap → `on_remote_button` | USB 报告 → 物理按键学习表 → 映射状态机 |
| 触发识别 | 单击、2–4 连击、独立长按 | `mapping.rs`：同类触发，USB 工作线程按时间推进，不等待或排队回放坐标 |
| 动作配置 | `button_bindings`、`multi_click_bindings`、`long_press_bindings` | 相同三类配置字段，保存在独立 `hisense.json` |
| 组合键编辑 | 实际键盘捕获与 `VoiceShortcutComposer` | 复用快捷键捕获会话和同一个手动组合组件，写入选中的触发槽位 |
| 鼠标移动 | 四个方向、1–100 px 步幅、按住加速 | 同样的参数；次数结算动作走一次位移，基础按住或独立长按约每 16 ms 推进，最高基础步幅的四倍 |
| ChatGPT 动作 | 打开并聚焦输入框 | 直接复用 `chatgpt_focus`，放在独立线程以免阻塞 UWB 采样 |
| 配置迁移 | 带格式与版本的映射 JSON | 海信专用格式、版本校验、内容校验与失败保留；不导入设备学习或其他设置 |

小米语音键在上游是专用通道。海信继续允许所有实体按键映射语音，沿用接收器麦克风与已有输入法快捷键路径，不能直接照搬小米专用键分支。

## 触发行为

- 只配置基础动作时，保留原来的按下执行、松开释放。
- 配置独立长按后，短按在松开时执行；长按达到阈值后只执行长按动作。
- 配置连击后，等待下一次点击，执行实际次数对应的动作，不同时发送较低次数的动作。达到已配置的最高次数时立即结算。未配置的次数不回退成单击。
- 连击间隔默认 300 ms，可调 150–800 ms；独立长按沿用上游 280 ms，音量键为 400 ms。UWB 确认的长按阈值仍由原来的指向设置独立控制。
- 按住支持持续键盘、语音、鼠标移动或触摸拖动；文字输入、启动应用和打开 ChatGPT 执行一次。
- 相同逻辑按键的多个输入来源合并按下与抬起，避免同一次物理操作被计算成多击。

## 保留 UWB 与语音的即时响应

基础动作为“确定键（随模式）”“循环切换三种模式”“按住触摸拖动”或“语音输入”时，继续直接处理按下与松开，不进入连击识别。

这些动作的独立触发按钮禁用。改成普通基础动作后可配置连击与长按；再切回即时动作时，清除该键不兼容的独立连击与长按，避免已配置但不执行的隐藏状态。语音输入与按住拖动也可放入独立长按槽位；连击完成时按键已松开，因此连击不提供这些持续动作。

三种 UWB 模式、AI 循环、触摸圆点、防抖与慢移精细瞄准均保留。

## 配置与执行的边界

导出文件仅含单击、长按、连击和连击间隔。海信使用 `nexus-prime-hisense-mappings` 格式、版本 1；不会误把小米文件当作海信配置。

导入先完整校验，再将映射应用到当前配置副本，成功写入磁盘后才更新运行配置。文件格式、内容、保存任一步失败，运行配置不变。未知按键、超范围键码、非法鼠标参数与不兼容即时动作被拒绝，文件大小限制为 1 MB。

重置同样只恢复映射部分。语音预设、指向与防抖参数、麦克风和接收器按键学习数据保持当前值。旧配置缺少新增字段时获得空的独立长按/连击和 300 ms 间隔，保留原有按键动作。

暂停、断连、进入快捷键录入、开始按键学习或更新配置时，取消待识别的连击、长按和临时动作，并释放已注入的输出，避免之后补发或卡键。

## 本轮验证

- 前端构建与 Rust 全目标检查通过。
- 前端 92 项测试通过；海信后端 28 项测试通过，需接收器独占访问的硬件测试未运行。
- 调试程序构建通过；保持开发版联调，不制作安装包。
- 自动检查覆盖次数区分、长按取消短按、重复来源、取消后的无回放、旧配置默认值、导入失败不修改配置、编辑槽位隔离、语音录入、UI 弹窗及既有 UWB/精度逻辑。
- 真实遥控器的连击时序、长按释放、鼠标动作与语音完整识别仍需用户实测，构建和逻辑测试不代表这些已验收。
